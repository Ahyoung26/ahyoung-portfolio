Problem Discovery Process

01

데이터에서 시작합니다

사용자 행동 데이터와 이탈 패턴에서 서비스 문제를 발견하고, 팀이 공감할 수 있는 근거를 만듭니다.

02

흐름의 단절을 찾습니다

기능이 아니라 사용자 여정의 어느 지점에서 경험이 끊기는지, 왜 이탈하는지를 구조적으로 파악합니다.

03

운영까지 함께 설계합니다

UX 흐름과 운영 정책을 동시에 고려해, 실제로 서비스가 작동하고 유지될 수 있는 구조를 만듭니다.

  • 사용자 행동 데이터 — 이탈 패턴과 행동 흐름을 기반으로 문제 지점을 특정
  • 흐름의 단절 — 퍼널 내 어느 단계에서 경험이 끊기는지 구조적으로 파악
  • 운영 리스크 — 서비스 운영 단계의 비효율과 반복 업무 구조 분석

Philosophy

개요

데이터 기반 문제 정의에서 출발해 UX 흐름과 운영 구조를 함께 설계하는 6단계 프로세스를 정리했습니다. 또한 서비스 기획자로서 일관되게 가져가는 관점과 철학을 함께 담았습니다.

Working Process

문제를 구조화하고,
실제 운영 가능한 흐름으로 연결합니다.

데이터 수집에서 검증까지, 반복 가능한 문제 해결 구조로 접근합니다.

01 · Problem Discovery

현상 파악 & 가설 수립

서비스 현상을 관찰하고 문제가 될 수 있는 지점을 가설로 정리합니다.

02 · Data Analysis

행동 데이터 분석

퍼널 데이터와 사용자 이벤트 로그를 기반으로 이탈 패턴과 문제 지점을 특정합니다.

03 · User Flow Map

사용자 여정 분석

실제 사용 흐름을 시각화하고 서비스 단절 지점을 구조적으로 파악합니다.

04 · Hypothesis

문제 정의 & 근거

데이터와 관찰을 근거로 해결해야 할 핵심 문제를 구조적으로 정의합니다.

05 · Solution Design

UX / 운영 구조 설계

UX 흐름과 운영 정책을 함께 고려한 실제로 작동 가능한 해결 방법을 설계합니다.

06 · Validation

검증 & 반복 개선

변경 이후 데이터를 다시 수집해 가설을 검증하고, 구조를 반복적으로 개선합니다.

Philosophy

서비스는 기능보다 흐름 안에서
경험된다고 생각합니다.

기능의 집합이 아니라, 사용자와 운영 환경 안에서 하나의 흐름으로 작동하는 구조를 설계합니다.

서비스를 기능 모음이 아니라
사용자와 운영 환경 안에서
하나의 흐름으로 작동하는 구조로 봅니다.

데이터에서 문제를 발견하고, 사용자 여정에서 단절을 찾고, 운영 가능한 구조로 해결하는 과정을 반복합니다.
좋은 기획은 사용자와 서비스 운영 양측에서 자연스럽게 작동해야 한다고 믿습니다.
