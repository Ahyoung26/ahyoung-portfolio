Problem → Solution Flow

서비스 문제는 단순히 기능 부족이 아니라, 사용자 흐름이 끊기거나 운영 구조가 비효율적으로 설계된 경우 발생한다고 생각합니다.

  • 사용자 행동 데이터 — 이탈 패턴과 행동 흐름을 기반으로 문제 지점을 특정
  • 이탈 지점 — 퍼널 내 어느 단계에서 경험이 끊기는지 구조적으로 파악
  • 운영 리스크 — 서비스 운영 단계의 비효율과 반복 업무 구조를 함께 분석
  • 반복 업무 구조 — 장기적으로 확장 가능한 해결 방법을 설계

공유 페이지가 '서비스 진입로'가 아니라
'종착지'처럼 작동하고 있었습니다.

외부 페이지를 통해 대규모 유입은 발생하고 있었지만, 다운로드 이후 대부분의 사용자가 추가 행동 없이 이탈하고 있었습니다.

  • 다운로드 수는 높지만, Session Start와 Signup 전환율은 현저히 낮은 상태
  • 다운로드가 완료되는 시점이 사용자 여정의 Dead-End로 설계되어 있었음
  • 서비스의 핵심 가치를 경험할 기회 없이 이탈 — 잠재 사용자의 활성화 실패

가설: 다운로드 이후에도 핵심 기능을 자연스럽게 노출한다면, 단발성 사용자가 서비스 탐색 사용자로 전환될 수 있다고 판단했습니다.
